# 09. 검증대상 버전·파일목록

이 문서는 받은 공개 패키지의 파일과 동결 모델을 식별하는 방법을 설명합니다. 검증 기록에는 사용한 Git 커밋, 실행한 점검 범위, 실행 결과를 함께 남깁니다.

## 1. 검증대상 버전

| 항목 | 내용 |
| --- | --- |
| 검증 대상 | 디노테퓨란 CatBoost 95열 · 검증 Optuna trial 3 · Window 90일 |
| 모델 버전 문자열 | `CatBoost 95 / 11.13 pest count / validation Optuna` |
| 모델 저장 정보 | 검증 Optuna trial 3, 학습에서 평가한 178회 중 선정된 138개 트리 |
| 입력 계약 | 95개 피처 이름과 순서, 범주형 4열 위치, H=1~60 |
| 최종 검출 임계값 | `0.0583612434566021` |
| 과거 테스트 검사기간 | 2025-07-01~2026-06-30 |
| 테스트 적용 방식 | 검증에서 선택한 모델과 임계값을 고정하여 44,175검체의 H=1~60에 적용 |

### 확인하려는 대상별 식별값

| 확인 대상 | 비교하는 값 | 확인할 수 있는 범위 |
| --- | --- | --- |
| Git 배포 시점 | 내려받은 커밋 SHA | 문서·코드·공개 집계 파일의 특정 버전. Clone한 경우 루트에서 `git rev-parse HEAD`로 조회 |
| 공개 파일 | 파일 목록의 `file`, `bytes`, `sha256` | 받은 파일이 목록에 기록된 배포 파일과 바이트 단위로 일치하는지 점검 |
| 동결 모델 바이너리 | 모델 설정의 `model_sha256` | 별도로 받은 `model.cbm`이 95열 trial 3의 바이너리인지 확인 |
| 추론 조건 | 모델 설정의 피처 순서·범주형 위치·트리 수·임계값 | 같은 입력 정의와 모델을 사용해 합성 예제의 확률과 판정을 대조 |

모델 파일이 필요한 점검은 [모델 설정](../02_학습모델파일/model_settings.json)의 `model_sha256`을 기준으로 합니다. 공개 패키지 목록에서 `model_settings.json`에 해당하는 해시는 JSON 파일 자체의 바이트를 뜻합니다. [동결 모델의 설정과 제공 범위](../02_학습모델파일/README.md)

## 2. 배포 파일 목록과 SHA-256

목록에는 README와 제출자료 확인표, 소스코드 및 실행기, 모델 설정과 Optuna 기록, 분할·피처 정의, 성능표·그래프, 합성 입출력이 포함됩니다.

| 열 | 의미 |
| --- | --- |
| `file` | 저장소 루트 기준 상대 경로 |
| `bytes` | 배포본 파일의 바이트 수. 텍스트도 글자 수 대신 바이트로 비교 |
| `sha256` | 배포본 파일 바이트에서 구한 64자리 SHA-256 |

텍스트 파일은 LF 줄바꿈으로 기록했습니다. 파일을 CRLF나 다른 인코딩으로 다시 저장하면 화면에 같은 내용이 보여도 바이트 수 또는 SHA-256이 달라질 수 있습니다. 목록 파일 자체의 변경 이력은 Git 커밋으로 추적합니다. 로컬에서 생성한 점검 보고서와 별도로 받은 동결 모델은 각자의 실행 기록과 모델 해시로 관리합니다. [공개 배포 파일 목록](파일목록_SHA256.csv)

## 3. 배포 상태 확인

1. 받은 패키지의 루트에서 실행합니다. 아래 두 명령은 같은 공개 점검을 수행합니다.

   ```powershell
   python -B "01_소스코드/verify_package.py"
   .\검증_실행.ps1 -ReportDir "점검/배포확인"
   ```

2. 파일 무결성 검사에서 경로·크기·SHA-256이 일치해야 집계와 예제를 계속 점검합니다. 출력에서 집계 12행, H별 지표 240행, 95개 입력 피처, 합성 예제 3행 점검을 확인합니다. `-ReportDir`를 지정했다면 `점검/배포확인/검증_결과.json`에서 `passed: true`와 모델 미지정 상태 `native_model.status: skipped`를 확인합니다.
3. 동결 모델을 확인할 때는 PowerShell의 `-Model` 또는 Python의 `--model`에 해당 파일 경로를 지정합니다. 바이너리의 SHA-256과 구조를 대조한 뒤 합성 입력 3행을 추론합니다. 성공한 보고서에는 `native_model.status: passed`와 실제 모델 해시, 비교한 행 수 및 최대 확률 차이가 기록됩니다.

오류 메시지에 `Size mismatch` 또는 `SHA-256 mismatch`가 표시되면 보고된 파일 경로부터 확인합니다. 공개 파일의 경우 같은 커밋의 원본을 다시 받아 대조하고, 모델 파일의 경우 설정에 기록된 해시와 제공받은 모델의 해시를 비교합니다. PowerShell에서 파일 한 개의 해시는 `Get-FileHash -Algorithm SHA256 -LiteralPath "받은_파일_경로"`로 확인할 수 있습니다. [실행 방법과 점검 옵션](../04_실행환경_실행방법/README.md)
