# 02. 학습모델파일

검증 대상은 디노테퓨란 CatBoost 95열 · 검증 Optuna trial 3 · Window 90일 버전입니다. 검증에서 선택한 모델과 임계값을 동결해 과거 테스트 기간의 검체에 적용했습니다.

## 1. 모델 버전과 파일

| 항목 | 내용 |
| --- | --- |
| 모델과 예측 대상 | CatBoost 이진분류, 식품 검체의 디노테퓨란 검출 여부 |
| 학습 입력 | 95열, Window 90일, seed 42 |
| 추가한 입력 | 품목별 병해충 위험 지수. 11.13 목록에서 품목군×세부품목별 고유 방제 대상명 수를 집계. 모델 입력 열 이름은 `dinotefuran_pest_target_name_count` |
| 모델 선정 | 검증 Optuna trial 3 |
| 학습과 저장 | 최대 400회 설정, 실제 178회 학습, 최적 시점의 138개 트리 저장 |
| 모델 파일 형식 | CatBoost 네이티브 `.cbm` |
| 모델 파일 SHA-256 | `1606487d29220860e20edbe9d60ecdc9d4559f8d9f1c88b4486a9c31ea7ee8ca` |

[모델 설정](model_settings.json)의 `feature_order`에는 95개 피처 이름과 순서가 들어 있습니다. `categorical_indices_zero_based`의 56·57·58·59는 순서대로 검사 경로, 지역, 품목군, 세부품목입니다. `training_parameters`는 학습 설정, `selection`은 선정 당시 검증 지표, `threshold`는 판정에 사용하는 임계값입니다. 각 열의 단위와 계산 방법은 [95열 입력 정의](../03_학습검증평가데이터_분할정보/입력정의_95열.csv)에서 확인할 수 있습니다.

공개 패키지에는 모델 설정과 실험 기록을 제공합니다. 추론에 쓰는 동결 `model.cbm`은 승인된 경로로 받아 로컬에 저장한 뒤 실행 명령에 지정합니다. 파일 SHA-256이 설정과 일치해야 해당 바이너리로 추론할 수 있습니다. [배포 파일과 모델의 식별 기준](../09_검증대상버전_파일목록/README.md)

## 2. 검증 선정 기준과 검출 판정

검증은 34,256검체의 H=1~60을 펼친 2,055,360평가쌍에서 진행했습니다. 이 중 실제 검출은 1,406검체에 대응하는 84,360평가쌍입니다. 기상 8종 비교 모델의 검증 Precision에서 2%p를 뺀 `0.12127633716066934`를 하한으로 적용했습니다.

1. 각 모델의 검증 확률을 내림차순으로 정렬하고, 같은 확률의 행을 묶어 임계값 후보마다 Precision과 Recall을 계산했습니다.
2. Precision 하한을 만족하는 후보 중 Recall이 가장 높은 지점을 선택했습니다. Recall이 같을 때는 Precision이 높은 후보를 우선했습니다.
3. 같은 기준으로 트리 수와 trial을 비교했습니다. 15개 trial을 기록했고 8개가 완료, 7개가 가지치기됐습니다. 완료 trial 중 검증 Recall이 가장 높은 trial 3을 선택했습니다.
4. trial 3의 모델을 불러와 당시 검증 점수와 판정을 다시 대조했습니다. 확률 최대 절대차는 0이었고 판정도 일치했습니다. 그 모델과 검증 임계값을 고정해 과거 테스트의 모든 H에 적용했습니다.

| 항목 | 저장 값 |
| --- | ---: |
| 적용한 검증 Precision 하한 | `0.12127633716066934` |
| 검증 Precision | `0.12128153218691112` (12.12815%) |
| 검증 Recall | `0.9238975817923186` (92.38976%) |
| 검증 선정 임계값 | `0.0583612434566021` |

선정 지점에서 TP는 77,940, FN은 6,420, FP는 564,697평가쌍입니다. Precision은 `77,940 ÷ (77,940 + 564,697)`, Recall은 `77,940 ÷ (77,940 + 6,420)`으로 계산합니다. 설정 파일의 `selection.value`는 Recall과 Precision 동률 기준을 한 숫자로 표현한 Optuna 점수 `(TP + 0.5 × Precision) ÷ (실제 검출 평가쌍 수 + 1)`입니다. 보고용 Recall과 Precision은 같은 파일의 `selection.recall`과 `selection.precision`에서 확인합니다. [혼동행렬과 지표 해설](../05_성능검증_상세자료/README.md)

모델 검출 확률이 임계값 `0.0583612434566021` 이상이면 검출 예측 `1`, 미만이면 불검출 예측 `0`입니다. 표에서는 읽기 좋게 값을 반올림하고, 실제 판정 코드는 동결 모델의 점수와 저장 설정을 사용합니다. [합성 입력의 확률과 판정 예시](../06_입출력정의_샘플/README.md)

## 3. Optuna 탐색과 선정된 학습 설정

[`optuna_trials.csv`](optuna_trials.csv)는 trial 번호, 상태, 탐색 파라미터, 검증 Precision·Recall·임계값, 저장한 트리 수를 담고 있습니다. `PRUNED` 행은 중간 검증 지표를 기준으로 종료돼 최종 점수·임계값 칸이 비어 있습니다.

| trial | 검증 Recall | 검증 Precision | 임계값 | 저장 트리 | 기록의 의미 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 0 | 84.03983% | 12.17998% | 0.0706868991 | 30 | 95열 미튜닝 모델의 바이너리와 저장 검증 점수를 재사용한 기준 |
| 1 | 89.71195% | 12.14678% | 0.0464627407 | 29 | trial 0과 같은 5개 탐색 파라미터에서 새로 적합하고 최적 트리 수를 선택 |
| 3 | 92.38976% | 12.12815% | 0.0583612435 | 138 | Precision 하한을 만족한 검증 Recall 최상위 |
| 14 | 92.30085% | 12.13047% | 0.0645897463 | 82 | 완료 trial 중 검증 Recall 차상위 |

탐색은 TPE(seed 42, 초기 trial 3개)로 수행했습니다. 중앙값 가지치기는 초기 trial 3개와 워밍업 80회 설정을 사용했습니다. 새로 적합한 trial은 최대 400회와 검증 지표 기준 40회 조기 종료를 적용했습니다. 각 trial에서 최고 검증 지표를 얻은 시점까지 트리를 남겼습니다. 최종 trial 3의 `trained_steps=178`은 평가한 학습 반복 수이고, `trees=138`은 추론에 쓰는 저장 트리 수입니다.

| 파라미터 | 탐색 범위 | trial 3 값 |
| --- | --- | ---: |
| `depth` | 정수 4~8 | 8 |
| `learning_rate` | 0.01~0.15, 로그 간격 | 0.01016373 |
| `l2_leaf_reg` | 0.1~20, 로그 간격 | 0.10407984 |
| `random_strength` | 0~2 | 0.03592375 |
| `bagging_temperature` | 0~1 | 0.88565633 |

고정 설정은 CPU, `Logloss`, Bayesian bootstrap, seed 42, `border_count=64`, 스레드 8개입니다. 표의 값은 표시용으로 반올림했습니다. [원정밀도 모델 설정](model_settings.json)

## 4. 모델로 확인하는 항목

추론 스크립트는 `model.cbm`의 SHA-256을 먼저 확인하고, 불러온 모델의 피처 이름·순서, 범주형 열 위치, 트리 수, 클래스 순서 `[0, 1]`을 대조합니다. 이 대조가 끝나면 클래스 `1`의 확률을 사용해 각 입력 행에 확률·임계값·판정을 추가합니다.

기본 패키지 점검에는 공개 설정과 저장된 예제의 정합성 확인이 포함됩니다. 모델 파일을 지정하면 합성 입력 3행을 새로 추론합니다. 94열 비교 결과는 성능표에서 검산할 수 있으며, 모델 파일을 지정하는 이 실행 절차의 대상은 95열 trial 3입니다. [실행 방법](../04_실행환경_실행방법/README.md)
