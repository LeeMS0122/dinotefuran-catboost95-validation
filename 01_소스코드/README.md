# 01. 소스코드

검증 대상은 CatBoost 95열, Window 90일, 검증 Optuna trial 3입니다. 소스에는 공개 패키지 점검, 동결 모델 추론, 검증·테스트 집계 검산의 실행 경로가 들어 있습니다.

## 1. 파일과 실행 흐름

| 파일 | 읽는 자료 | 처리 및 반환 |
| --- | --- | --- |

## 2. 공개 패키지와 성능표 검산

저장소 루트에서 공개 패키지를 점검합니다.

```bash
python -B "01_소스코드/verify_package.py"
```

1. 배포 목록에 적힌 파일의 바이트 수와 SHA-256을 비교합니다. 목록에 기록한 필수 파일이 실제로 있는지도 확인합니다.
2. 모델 설정에서 95개 고유 피처, 범주형 위치 56~59(0부터 시작), Window 90일, H=1~60, trial 3의 트리 138개 및 동결 임계값을 확인합니다.
3. H마다 `TP + FN`과 `FP + TN`을 분할별 실제 검출·불검출 검체 수에 대조합니다. 혼동행렬로 Accuracy·Precision·Recall·F1·F4·검사 축소율을 다시 계산합니다. H=1~60 요약은 합산한 혼동행렬에서 계산하며, H=42~55 요약은 해당 14개 H의 비율을 산술평균하고 건수를 합산했는지 확인합니다.
4. 합성 입력 3행의 95개 피처, D·M·H 관계, 출력의 원본 입력값 보존, 저장한 검출 확률과 임계값으로 정한 판정의 일치 여부를 확인합니다. `--model`을 지정하면 같은 3행을 실제로 추론해 기대 출력과 다시 비교합니다.

공개 집계표에서 재계산하는 것은 혼동행렬 기반 지표입니다. 전체 H의 ROC-AUC·PR-AUC·AP를 확률 순위에서 새로 계산하려면 검체×H별 원래 점수와 실제값이 필요합니다. 공개 점검에서는 이 지표의 범위와 해당 H의 요약 규칙을 확인합니다.

| 원하는 점검 | 저장소 루트에서 실행할 명령 | 확인 결과 |
| --- | --- | --- |
| 공개 패키지 전체 | `python -B "01_소스코드/verify_package.py"` | 파일 31개, 집계 12행, H별 240행, 합성 예제 3행 점검 |
| 성능 CSV 두 개만 검산 | `python -B "01_소스코드/final_model95/verify_results.py" "05_성능검증_상세자료"` | `Verified 12 summary rows and 240 horizon rows.` 출력 |

## 3. CSV 추론 코드가 처리하는 순서

1. 설정 JSON의 피처 목록과 모델 파일 SHA-256을 읽습니다. 모델 해시가 일치하면 CatBoost로 불러와 95열의 이름·순서, 범주형 위치, 트리 수, 클래스 순서 `[0, 1]`을 검증합니다.
2. 입력 헤더에서 이름으로 95개 열을 찾고 모델 설정의 순서로 배열합니다. 수치형 열을 `float32`로 변환하고, 네 범주형 열의 정수 코드를 범주 문자열로 전달합니다. 검체 ID와 날짜 같은 메타데이터는 결과에 보존합니다.
3. 행을 최대 32,768개씩 읽어 CatBoost의 클래스 `1` 확률을 얻은 뒤, `float32` 확률에 동결 임계값을 적용합니다. 입력과 같은 순서로 원래 열과 예측 3열을 임시 CSV에 씁니다.
4. 모든 행이 성공하면 임시 파일을 지정한 출력 경로로 옮깁니다. 중간 행에서 실패하면 오류를 반환하고 기존 출력 파일이 있으면 보존합니다. 입력·모델·설정 파일과 동일한 위치를 출력 경로로 지정하면 오류로 처리합니다.

추론을 시작할 때는 기준일과 학습 당시 전처리를 이미 적용한 95열 CSV가 필요합니다. 원천자료 선택과 요약, 결측 대체, 범주 사전 적용은 입력을 준비하는 과정입니다. [데이터 분할과 입력 정의](../03_학습검증평가데이터_분할정보/README.md) · [데이터 처리 및 누수점검](../08_데이터처리_누수점검/README.md) · [Optuna 선택 기준과 trial 결과](../02_학습모델파일/README.md)

## 4. 코드 테스트
