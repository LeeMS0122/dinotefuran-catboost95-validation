# 06. 입출력 정의·샘플

검증 대상은 디노테퓨란 CatBoost 95열 · 검증 Optuna trial 3 · Window 90일 버전입니다.

## 1. 예측 단위와 날짜

과거 평가에서는 검체×예측거리 H를 한 행으로 구성했습니다. 검사일 M과 H가 정해지면 기준일은 `D = M - H`입니다. 기준일 D를 고정한 예제에서는 대상일을 `M = D + H`로 정합니다. H는 1~60일이고 모델 입력 `horizon_scaled`는 `(H - 1) / 59`입니다.

| 입력을 조립하는 예 | 기준일 D | 검사일 또는 대상일 M | H | 해석 |
| --- | --- | --- | ---: | --- |
| 검사일 고정 | 2025-07-30 | 2025-07-31 | 1 | 같은 검체를 검사 1일 전까지의 자료로 예측 |
| 검사일 고정 | 2025-07-01 | 2025-07-31 | 30 | 같은 검체를 검사 30일 전까지의 자료로 예측 |
| 기준일 고정 | 2025-07-01 | 2025-07-02 | 1 | 합성 예제에서 동일한 기준일까지의 정보로 다음 날을 지정 |
| 기준일 고정 | 2025-07-01 | 2025-08-30 | 60 | 같은 합성 사례에서 대상일을 60일 뒤로 지정 |

검증 당시의 입력을 재현하려면 D에 맞는 기상·토양 요약과 파생변수를 조립하고 학습에서 정한 범주 사전, 결측 대체, 연도 표준화 규칙을 적용합니다. 방제 대상명 수에는 11.13 목록의 품목군×세부품목별 고유 명칭 집계를 사용합니다. [95개 열의 전체 순서와 정의](../03_학습검증평가데이터_분할정보/입력정의_95열.csv) · [기준일을 적용한 전처리](../08_데이터처리_누수점검/README.md)

## 2. 입력 CSV

| 항목 | 규칙 |
| --- | --- |
| 파일 형식 | 헤더가 있는 UTF-8 CSV. BOM 유무 모두 읽을 수 있음 |
| 필수 피처 | [모델 설정](../02_학습모델파일/model_settings.json)의 `feature_order`에 기록한 95개 이름을 헤더에 포함. 스크립트가 이 순서대로 모델에 전달 |
| 범주형 4열 | `source_route`, `region`, `product_group`, `product_detail`. 모델 위치는 0부터 세어 56~59. 각 값을 학습 당시와 같은 사전에서 조립한 0 이상의 정수 코드로 입력. 코드 자체는 `2^31` 미만이고 `float32` 변환 전후 정수값이 같아야 함 |
| 수치형 91열 | 동결 전처리를 적용한 유한 수치. 결측 대체값과 해당 결측 표시 열도 모델 설정에 맞게 입력. 빈칸·`NaN`·무한대는 오류로 처리 |
| 선택 메타데이터 | 검체 ID, 지역·품목명, D, M, H 등. 결과에서 행을 식별하는 데 사용하며 입력 순서와 값이 유지됨 |

CSV 헤더에 필수 피처 이름 95개를 정확히 표기하면 입력에서 열이 놓인 순서와 관계없이 스크립트가 모델 순서로 재배열합니다. 빈 헤더, 중복 헤더, 결과 전용 열 `probability`, `threshold`, `prediction`, 헤더와 칸 수가 다른 행은 오류로 처리합니다.

합성 입력 CSV에는 피처 95열과 다음 메타데이터 6열이 있어 총 101열입니다.

| 메타데이터 | 예제 값 | 용도 |
| --- | --- | --- |
| `sample_id` | `DEMO-01` | 한 입력 행을 식별. 세 합성 행에 고유 값 부여 |
| `case_id` | `SYNTHETIC-001` | 동일한 합성 사례의 H별 행을 묶는 값 |
| `scope` | `synthetic_smoke` | 예제 구분 |
| `D` | `2025-07-01` | 예측 기준일 |
| `M` | `2025-07-02` | 평가에서는 검사일, 고정 기준일 예제에서는 예측 대상일 |
| `H` | `1` | D와 M 사이의 일수. 모델에 들어가는 값은 별도의 `horizon_scaled` |

`predict` 명령은 이 메타데이터를 그대로 복사하고 95개 피처에 저장된 값으로 추론합니다. 검증할 자료를 새로 조립할 때에는 D·M·H의 관계와 `horizon_scaled` 값이 맞는지 먼저 확인합니다. 공개 합성 예제는 점검 스크립트가 D·M·H의 일치 여부를 확인합니다.

## 3. 출력 CSV

출력은 UTF-8 BOM CSV입니다. 입력의 행 순서와 열 순서, 식별값과 앞자리가 0인 코드 표기를 보존하고 아래 세 열을 오른쪽에 추가합니다. 합성 예제 출력은 104열입니다.

| 추가 열 | 의미 |
| --- | --- |
| `probability` | CatBoost가 계산한 검출 확률을 `float32`로 변환한 값. 범위는 0~1 |
| `threshold` | 검증에서 선택한 동결 임계값 `0.0583612434566021` |
| `prediction` | `probability >= threshold`이면 검출 예측 `1`, 미만이면 불검출 예측 `0` |

출력의 `prediction`은 모델의 예측입니다. 실제 검사 결과가 있는 과거 평가에서는 검체 ID와 H로 검사 라벨을 연결해 판정과 대조합니다. 공개 합성 예제의 3행은 입출력 확인용이라 실제 검사 라벨이 없습니다.

## 4. 합성 입력과 기대 출력

[합성 입력 CSV](prepared_features_example.csv)는 기준일과 기상·토양·품목 입력을 고정한 상태에서 H를 1, 30, 60으로 바꾼 3행입니다. [기대 출력 CSV](example_output.csv)는 동결 모델로 이 입력을 미리 실행해 저장한 결과입니다.

| `sample_id` | 대상일 M | H | `horizon_scaled` | 검출 확률 | 동결 임계값 | 예측값 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| DEMO-01 | 2025-07-02 | 1 | 0.0 | 0.13407738506793976 | 0.0583612434566021 | 1 (검출 예측) |
| DEMO-30 | 2025-07-31 | 30 | 0.4915254237288136 | 0.13407738506793976 | 0.0583612434566021 | 1 (검출 예측) |
| DEMO-60 | 2025-08-30 | 60 | 1.0 | 0.13407738506793976 | 0.0583612434566021 | 1 (검출 예측) |

동결 모델의 트리에는 `horizon_scaled`로 직접 분기하는 경우가 없어 날짜와 나머지 모델 입력을 고정하면 세 행의 확률이 같게 나옵니다. 과거 성능 평가에서는 M을 고정하고 H마다 D를 다시 계산해 기상·토양·달력 입력을 조립했습니다.

예를 들어 DEMO-30의 저장 확률은 약 13.41%입니다. 동결 임계값 약 5.84% 이상이므로 `prediction=1`입니다. 확률과 임계값은 CSV의 소수값을 기준으로 판정하고, 백분율의 반올림값은 읽기 편하도록 표시합니다.

## 5. 예제를 확인하는 두 방법

- **저장소를 내려받아 확인** · 기대 출력 CSV를 열어 세 예측행을 볼 수 있습니다. 검증 스크립트는 모델 경로 없이도 입력 스키마와 D·M·H, 출력에 보존된 입력, 저장 확률·임계값·판정의 일치 여부를 점검합니다.
- **동결 모델로 재계산** · `검증_실행.ps1`에 `-Model`을 지정하면 합성 3행을 다시 추론해 저장된 기대 출력과 비교합니다. 사용자 지정 경로에 새 CSV를 남기려면 `predict` 명령으로 입력과 출력 경로를 지정합니다.
